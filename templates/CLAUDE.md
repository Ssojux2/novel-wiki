# {{TITLE}} — 집필 규칙 (novel-wiki)

이 폴더는 novel-wiki 플러그인으로 관리하는 장편 소설 프로젝트다.
LLM Wiki 패턴을 쓴다: **원고(canon)는 작가가 쓰고, 바이블은 LLM이 원고에서 컴파일한다.**

- 장르: {{GENRE}}
- 시점(POV): {{POV}}  ← 예: 3인칭 제한(한서윤), 1인칭
- 시제: {{TENSE}}  ← 예: 과거형
- 목표 분량: {{LENGTH}}

## 레이어와 소유권

| 폴더 | 내용 | 누가 쓰나 |
|---|---|---|
| `manuscript/` | 원고 `chNN.md` (정본, canon) | 작가. LLM은 **요청받았을 때만** 수정 |
| `notes/` | 아이디어, 자료조사, 메모 (raw) | 작가. LLM은 읽기만 |
| `outline/` | 구조 설계(`architecture.md`), 장 비트(`chNN.md`) | 작가 + LLM 공동 |
| `bible/` | 스토리 바이블 (위키) | **LLM 전용**. 작가는 읽고 지시만 |
| `packs/` | 장면별 맥락 팩 | 스크립트 + LLM |
| `reviews/` | 리뷰·린트·AI티 리포트 | LLM |
| `builds/` | 합본 docx (빌드 결과물, 직접 수정 금지) | 스크립트 |
| `sessions/` | 세션 노트 | LLM |

## 절대 규칙

1. 원고와 바이블이 충돌하면 **원고가 이긴다**. 바이블을 고치고 `_log.md`에 남긴다.
2. 바이블끼리 충돌하면 두 주장을 모두 남기고 `> ⚠️ 모순:` 블록으로 표시한다.
3. 장면을 쓸 때는 **맥락 팩(`packs/`)에 있는 것만** 정본으로 취급한다. 팩에 없는 설정이 필요하면 지어내기 전에 작가에게 묻는다.
4. 상태는 시간축으로 기록한다. 인물·장소·세력·기술 페이지의 `## 상태 변화` 표에 장별 **변화분만** 적는다. 현재 상태를 덮어쓰지 않는다.
5. 고유명사 표기는 `bible/terms.md`가 정본이다.
6. 복선은 심는 즉시 `bible/threads.md`에 등록한다.
7. 세션을 끝낼 때 `sessions/YYYY-MM-DD_주제.md`에 2~5문장으로 무엇을 했고, 무엇을 정했고, 어디서 멈췄는지 남긴다.

## 문체 규칙

- 번역투 금지: "~에 있어서", "~을 통해"(남용), "~하지 않을 수 없었다", "시간/대화를 가졌다", 불필요한 "그는/그녀는".
- 감정 이름 대신 몸과 지각으로 보여준다. 필터어(느꼈다/보였다/들렸다/깨달았다)는 꼭 필요할 때만 쓴다.
- LLM 클리셰 금지 목록은 플러그인의 `references/korean-ai-isms.md`를 따른다.
- 대사 태그는 "말했다"를 기본으로 하되, 누가 말하는지 분명하면 생략한다.
- 장면 구분은 `* * *`. "장면 1" 같은 표지는 쓰지 않는다.
- 작가 고유 규칙: {{STYLE_NOTES}}

## 호흡 프로필
<!-- /novel-wiki:breath setup 으로 정한다. writer·stylist·reviewer·deslop이 읽는다. -->
- 목표 평균 문장 길이: 45        ← 서술문 기준, 공백 포함 글자 수
- 장문(80자 이상) 비율 목표: 25
- 짧은 문장(20자 이하) 연속 허용: 2
- 기본 모드: 감각정밀, 장문누적
- 장면별 모드: 묘사=장문누적, 액션=고밀도, 회상=기억굴절, 세계설명=민족지, 고립=반복리듬

## 집필 루프

```
/novel-wiki:go        세션 시작 (상태 요약 + 다음 할 일)
/novel-wiki:pack 12   12장 맥락 팩 생성
/novel-wiki:write 12  팩 기반 집필 (브레인스톰 → 선별 → 초고)
/novel-wiki:ingest 12 탈고한 장을 바이블에 컴파일
/novel-wiki:review 12 장 리뷰
/novel-wiki:lint      연속성 검사 (5장마다)
/novel-wiki:breath 12 호흡 측정·장문 묘사로 다시 쓰기
/novel-wiki:deslop 12 AI 티 제거
/novel-wiki:build     manuscript/ → builds/날짜/제목.docx (최종본 합본)
```

최종본은 `manuscript/`다. docx는 빌드 결과물이므로 고칠 게 있으면 원고를 고치고 다시 빌드한다.

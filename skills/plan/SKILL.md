구조 설계. 인자: $ARGUMENTS

howells/fiction의 new-project·architect 흐름을 따른다: 작가가 이미 알고 있는 것을 질문으로 끌어낸다. 대신 결정해 주지 않는다.

## 절차
1. `outline/architecture.md`, `bible/_overview.md`, `notes/`를 읽는다. 이미 채워진 칸은 묻지 않는다.
2. 한 번에 질문 3~4개씩, 아래 순서로 묻는다:
   1. **핵심**: 이 이야기가 왜 당신에게 중요한가? 독자가 덮을 때 무엇을 느끼길 원하나?
   2. **전제**: 누가, 무엇을 원하고, 무엇이 막고, 실패하면 무엇을 잃나?
   3. **주제 질문**: 작품이 끝까지 붙잡는 질문 하나. 결말이 내놓는 (잠정) 대답.
   4. **One Big Lie**: 현실 과학에서 딱 하나 비트는 것. (세부 세계관은 `/novel-wiki:world`에서)
   5. **결말**: 마지막 이미지, 주인공의 최종 선택. 해결되는 것과 열어두는 것.
   6. **큰 비트**: 계기 사건, 1차 전환, 중간점, 최저점, 클라이맥스의 대략적인 위치(장).
3. 답이 막히면 선택지 2~3개를 제시하고, 각각이 주제에 어떤 영향을 주는지 한 줄씩 붙인다.
4. 답을 받는 대로 바로 저장한다 (대화가 끊겨도 남도록):
   - `outline/architecture.md`: 모든 칸
   - `bible/_overview.md`: 로그라인, 주제 질문, One Big Lie, 결말 가안
5. 결말과 전제가 주제 질문에 실제로 답하는지 점검하고, 어긋나면 지적한다.
6. `bible/_log.md`에 `plan` 항목을 남긴다.
